# Kytto 1.0.8 for Windows

**Source release 1.0.8 · 15 October 2026.** The public release includes a Windows
x64 Inno Setup installer. It is unsigned (the PE file has no Authenticode
certificate table); its SHA-256 matches the attached sidecar. Its exact build
provenance and clean-profile installation were not independently verified during
release preparation. No ZIP is attached (see [`../release.md`](../release.md)).
This release ports the macOS 1.0.8 work. The user-facing list is in the repository
root `CHANGELOG.md` under `## [1.0.8]`; this file records source checks and the
remaining limits.

## What is new

- **Workspace and source filters and a matrix with a persistent inspector.** Scope
  (All sources / Global configurations / one workspace), Source (All source types /
  Configurations / Plugins & extensions / Custom & workspace sources) and Rows
  (Comfortable / Compact) compose with the text filter. Selecting a row opens the
  inspector beside the matrix (below it under 1100 px); Expand opens the full detail.
  Selection, focus and scroll survive a refresh. The sidebar is grouped Overview /
  Manage / Discover / Clients & sources, with workspaces nested under their client.
  MCP Library and Skills moved from the toolbar to the Discover group.
- **Registered plugins, read-only.** Active Claude Code (`installed_plugins.json` v2 plus
  user/project/local settings) and Codex (`[plugins.<id>]` plus the plugin cache)
  plugins show with their source and version. Kytto never switches, edits or copies
  a plugin; cache without a registration, disabled plugins and nested fixtures are
  not servers.
- **Contract Guard shows what changed**: bounded before/after for descriptions,
  annotations, schema fields, defaults and required arguments, with an explanation
  for confirmation and dry-run fields.
- **Remote Doctor over Streamable HTTP** with an explicit, native sign-in
  (S256 PKCE, loopback callback, resource-bound credentials in Windows Credential
  Manager). Checks never call a tool. Legacy SSE stays unsupported.
- **Portable setup**: export and import writable server definitions and profiles as
  JSON (compatible with the macOS app). Credentials, private paths and remote URLs
  become inputs typed on import; imported servers always start disabled; failures
  restore what was there; reviewed contract fingerprints are optional and stay
  pending until a fresh local check.
- **Report a bug** (private form) and **Report on GitHub** from Settings → Support,
  the tray's Help submenu, error notices and failure screens, plus a native recovery
  panel when the interface cannot load or the WebView2 browser process ends. The
  addresses are fixed and nothing is attached or submitted. No telemetry.
- Scope/Source/Rows pickers and the Profiles header actions follow the 1.0.8 design
  rules (`docs/design.md` §7.1.2 and §7.9).

## Verification

Run on Windows 11 with the .NET 10 SDK, from this source tree:

| Check | Result |
| --- | --- |
| `dotnet build` | 0 warnings, 0 errors |
| `dotnet test` | **967 Core + 248 App tests passed**, in two consecutive full runs (1.0.7.1 source: 551 + 77) |
| `npm test` (web) | **132 passed** (1.0.7.1 source: 48) |
| Real WebView2 recovery | 7 tests in `WebView2RecoveryIntegrationTests`: panel and reload, rebuild with working bridge and policy, a real renderer crash, a real kill of the window's own browser process, trusted clicks opening only the two report links |
| Web UI in a browser (`web/dev.html`, fixture data) | Measured at 1280×900 and 720×700 and in the reviewers' runs at 1024: no horizontal page overflow, the three pickers 36 px high, inspector 360 px beside the matrix and below it when narrow, Profiles actions one aligned group |
| Independent review | Four reviewers, each on one boundary (plugins and matrix UI; Contract Guard, remote checks and OAuth; portable setup and the write pipeline; shell, recovery and documentation). Serious findings were fixed with regression tests |

Review found and fixed, among others: batch-file launchers rejecting JSON and
URL-encoded arguments; a quadratic comparison a hostile server could use to freeze
a check; an export that could be pointed at a live config through a
`\\localhost\C$\...` share; an import that could shadow a plugin of the same name; a
sign-in callback lost when the browser reset the connection; schemas with a lone
surrogate breaking the pending-contract summary.

Tests that exercise credentials, configs and the write pipeline use temporary
homes and in-memory secret stores. Nothing here wrote to a real client
configuration or to Windows Credential Manager.

## Not verified

- **Remote sign-in against a real provider.** Only local mock servers were used: no
  live OAuth consent, provider quirks, real TLS or proxy. The credential chunk size
  was reasoned from the Credential Manager blob limit and tested against the
  in-memory store, not the OS store.
- **Native windows a person sees**: the sign-in confirmation, client-ID prompt,
  waiting window, portable export/import windows and the Windows file dialogs were
  built and tested through fakes and the router, but not operated by a person.
- **Real installs.** Plugin registrations were read in the formats the macOS
  reference and its fixtures use, not from a live Claude Code or Codex profile.
- **macOS interoperability.** The macOS fixture imports and its digest vectors match
  (five of five); the macOS app itself was not run against a Windows export.
- Windows animation setting mapping to reduced motion, keyboard use of the native
  select list inside WebView2, high-DPI rendering, a real GPU or renderer hang.
- The main window is drawn in software, because hardware-accelerated WPF painted
  nothing on the development machine; whether other machines need that is unknown.
- Installer, ZIP, signing and the clean-profile smoke run in `docs/release.md`.

## Known limits

- Plugin activation Kytto does not infer: session-only, account-synced and
  managed (enterprise) plugins, a Claude Code config directory moved with
  `CLAUDE_CONFIG_DIR`, and Codex plugins an account manages with no registration.
  Ambiguous cached versions are skipped with a diagnostic.
- Legacy SSE servers are not checked; remote gateway routing is not supported.
- A batch-file launcher refuses an argument `cmd.exe` would expand (for example
  `%PATH%`) or that contains a line break; it says so instead of starting it changed.
- Open, low severity: a tool description containing a lone surrogate shows as
  changed on every check; two overlapping checks of one remote server could both
  present a rotating refresh token; a token between 16,378 and 16,384 bytes signs in
  but fails the header limit; moving the clock back after an import makes the
  pending-reference store read as unreadable until it is deleted; a renamed or
  deleted server leaves its pending references behind; a name that is a plugin in
  one client and a config entry in another shows a clickable cell for the plugin's
  client, which the app then refuses.

## Compatibility

New commands: `setup.export`, `setup.previewImport`, `setup.applyImport`,
`setup.discardImport`, `health.signInRemote`, `health.forgetRemoteAuthorization`;
new capabilities `portable-setup`, `health.http`, `health.oauth`; the state gains
`pendingContractImports`, servers gain `originKind: "plugin"` and `source`, and a
Contract Guard change gains optional `details`. All are documented in
`docs/ipc.md`. Reporting and recovery add no IPC command. The page's transport tag
(`session`) belongs to the Windows `Web/bridge.js` shim and only makes the bridge
drop a reply addressed to a page that has since been reloaded or rebuilt.
Assembly and file versions are `1.0.8.0`; the project's `Version` is the single
source of the release number.
