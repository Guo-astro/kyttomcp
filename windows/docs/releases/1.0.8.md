# Kytto 1.0.8 for Windows

**Draft.** 1.0.8 is the name of the version in preparation, not a statement that
it has been built, signed or published; the latest published Windows build is
1.0.7.1. This release ports the macOS 1.0.8 work. Every Windows claim below is
marked **[pending verification]** until the results of the Windows build, test and
manual runs are recorded here; nothing in this file is a verified result yet. The
user-facing list belongs under `## [Unreleased]` in the repository's
`CHANGELOG.md`.

## Report a bug and interface recovery **[pending verification]**

- **Report a bug…** opens the private form at
  `https://kytto.jakubhecht.sk/#report-bug` (no account needed); **Report on
  GitHub…** opens the public issue chooser at
  `https://github.com/heyitsjakub/KyttoMCP/issues/new/choose` (a GitHub account is
  needed and the issue is public). Both open the system browser. The addresses are
  fixed: nothing about the failure — an error text, a path, a log line, a config
  value, the version or the machine — is ever put in them, and Kytto attaches and
  submits nothing. The reporter writes the report in the browser.
- They appear in Settings under **Support**, in the tray item's **Help** submenu,
  beside every error notice (the private form), on the startup failure screen
  (next to **Try again**), and next to a settings save that failed.
- An unhandled script error or promise rejection shows the same recovery screen
  with a generic message. The exception itself is never rendered or sent.
- If the web interface cannot load, or WebView2 reports a failed process, a
  native panel — independent of the page and of the IPC bridge — offers **Reload
  interface**, **Report a bug…** and **Report on GitHub…**. A lost renderer is
  recovered by navigating to the bundled app again; a lost browser process
  rebuilds the WebView2 control with its bridge and navigation policy. Reload
  only ever loads the bundled app origin and never re-sends a command or a config
  write. Repeated callbacks never stack a second panel, and a cancelled navigation
  never covers a working app.
- The external-navigation policy opens exactly those two addresses (only for a
  click, and only in the system browser) and refuses every other address,
  including the same host with anything added.
- No telemetry, no automatic crash reports, and no detection of a previous crash
  of the whole app: when the process dies the operating system handles it.

## Matrix, plugins, Contract Guard, Remote Doctor, portable setup **[pending verification]**

The rest of the macOS 1.0.8 work — workspace and source filters with a persistent

## Compatibility

No IPC command was added for reporting or recovery. The page's transport tag
(`session`, carried by every request and echoed in its reply) is part of the
Windows `Web/bridge.js` shim and not of `docs/ipc.md`: it only makes the bridge
drop a reply that belongs to a page that has since been reloaded or rebuilt.
Assembly and file versions are `1.0.8.0`; the project's `Version` is the single
source of the release number, as for earlier releases.
