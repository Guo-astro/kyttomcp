# Kytto 1.0.9 for Windows

**Source release 1.0.9 · 25 October 2026.** This release ports the macOS 1.0.9
work: support for the MCP 2026-07-28 revision and the fixes from a ten-area review
of the app. Every review item was first checked against the Windows code; the ones
the Windows code did not have are listed under *Already correct on Windows*. The
user-facing list is in the repository root `CHANGELOG.md` under `## [1.0.9]`; this
file records source checks and the remaining limits.

## What is new

- **MCP 2026-07-28.** Stdio checks send `server/discover` with the modern `_meta`
  first and wait up to `min(2 s, timeout/4)`. A discovery result naming 2026-07-28
  is a modern server (no handshake; server info from `_meta`); -32022 reports the
  versions the server does speak; -32020/-32021 also mean modern. Anything else,
  or silence, falls back to `initialize` on the same process, offering 2025-11-25
  and never 2026-07-28; a server that exits on the probe is started again; a
  strict server naming its revisions gets one retry; a late discovery answer is
  used. Handshake-era definitions skip the probe for the rest of the session.
  Server requests (`roots/list`, `ping`) are answered with -32601 and recorded.
- **Streamable HTTP** opens with `server/discover` (`MCP-Protocol-Version` and
  `Mcp-Method` headers, no session). 401 (or 403 with a challenge) needs sign-in;
  403/429/3xx stop the check; a modern error code in a 4xx body (read up to 16 KB,
  code and versions only) means modern; anything else falls back to `initialize`.
  A refused handshake is probed for the legacy HTTP+SSE transport (first event
  `endpoint`), which is reported as unsupported, as is plain HTTP off this machine.
- **Doctor** reports `deprecated-http-sse` (replacing `remote-check-unavailable`)
  and `deprecated-logging/-roots/-sampling`, and classifies a failure by its
  structured reason before matching words.

## Already correct on Windows

Discovery tracking the deny file before `.claude.json` exists; one count per name
when two sources share it; Codex refusing two tables that differ only in case;
the export package index only beside a public launcher and per-copy export
validation; the Doctor pin requiring the resolved file name to match the
command; provenance comparing only the package's own version; the protected
export-location check being case-insensitive; Cancel of an update download
taking effect at once. Not applicable on Windows (macOS mechanisms): SIGPIPE,
the spawn signal mask, translocation, `SMAppService` pending registration,
`rejectProtectionSpace`, the login-shell PATH, relative symlink targets in the
atomic writer (resolved by the OS through `ResolveLinkTarget`), and killing
health-check processes at quit (a Job Object with `KILL_ON_JOB_CLOSE` already
does it).

## Windows-specific translations

- Process shutdown closes the server's input, waits 200 ms, kills the tree and
  closes the job, then reads stderr to its end.
- Gateway mode refuses a helper started from inside a ZIP (`%TEMP%\Temp1_….zip`),
  the Windows counterpart of a translocated or disk-image app.
- The Gateway journal is opened per event under its mutex, so whichever helper
  notices 5 MB first can rename it to `.1` while other sessions keep running.
- The JSON parser stops at 128 levels; on .NET, running out of stack ends the
  process with no handler.
- Copying a JSON server into Codex is checked for unportable fields too (`headers`,
  `cwd`, `envFile`), not only Codex into JSON.

## Verification

Run on Windows 11 with the .NET 10 SDK, from this source tree:

| Check | Result |
| --- | --- |
| `dotnet build` | 0 warnings, 0 errors |
| `dotnet test` | **1040 Core + 251 App tests passed** in the second full run (1.0.8: 967 + 248). In the first, one loopback timing test (`ADeclaredOversizedBodyAndAStreamedOneBothFail`) failed under load and passed alone; the 1.0.8 baseline run had the same kind of flake in another loopback test |
| `npm test` (web) | **132 passed** |

New tests cover each ported item: modern-only, silent, exit-on-probe, strict,
prompts-only and server-request fake servers; modern, refusing and legacy-SSE
HTTP endpoints; rename and deny lists; per-file environment values; cross-format
refusals; TOML strictness; JSONC commas; nesting depth; per-file backup
retention; Contract Guard windows, invisible characters, repeated keys and the
review token; scanner characters; OAuth scopes, expiry, root metadata, step-up,
single-flight refresh and refresh-and-retry; Gateway inline env, refusals,
batches and journal rotation; portable labels and inputs; settings decoding;
skills behind junctions; abandoned update downloads.

Tests that exercise credentials, configs and the write pipeline use temporary
homes and in-memory secret stores. Nothing here wrote to a real client
configuration or to Windows Credential Manager.

## Not verified

- The 1280 px layout was checked by the web tests only, not looked at in the app.
- Installer, signing and the clean-profile smoke run in `docs/release.md`.

## Compatibility

`contract.acknowledge` takes an optional `reviewToken`, and `StateDTO`'s contract
alerts carry it; `servers.update` env entries take an optional `previousKey`.
Both are documented in `docs/ipc.md`. Stored health results gain an optional
`deprecatedFeatures`; remote failures gain the `LegacySse` kind (appended, so
stored numbers keep their meaning). Remote sign-ins are now keyed by the endpoint
without a trailing slash, so one saved for `…/mcp/` asks to sign in again.
Assembly and file versions are `1.0.9.0`; the project's `Version` is the single
source of the release number.
