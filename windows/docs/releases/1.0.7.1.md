# Kytto 1.0.7.1 for Windows

This release ports the macOS 1.0.7.1 fixes. The headline is Contract Guard: an
unreviewed change to what a server tells the model no longer disappears after
the next health check. The rest comes from an audit of the health checker, the
Gateway, the write pipeline and the web UI. The user-facing list is under
`## [Unreleased]` in the repository's `CHANGELOG.md`.

## Contract Guard and the Tool Safety Scanner

- **The baseline moves only on the first passing check and on acknowledgement.**
  Every passing check is compared against it, so changes accumulate, the alert
  keeps the time the change was first seen, and a server that reverts clears its
  own alert. `ServerMetadata` gains `lastPassingTools`; acknowledging after a
  failed check accepts the last passing contract.
- Input schemas are compared in canonical form (#12); bidi isolates
  U+2066–U+2069 are flagged (#13).
- Tools are read last-wins on a repeated key, schemas are scanned decoded, and
  phrase matching ignores soft hyphens, zero-width characters and line breaks.
- Doctor's safety scan, tool-name collisions and the context optimizer use the
  last passing tools, so a failing check cannot clear a finding.
- Metadata follows a rename and is forgotten on delete; a check that finishes
  after its server is gone, or that started before the stored one, is not
  recorded. An unreadable `metadata.json` is left alone and every write to it
  fails with a clear error instead of replacing it with `{}`.

## Health checks

- `tools/list` pagination is followed (up to 50 pages, repeated cursors stop it).
- Generic "authentication required" phrases count as waiting for sign-in only
  next to an authorization URL.
- The token counter slices pieces over 256 bytes, and a stdout line over 32 MB
  ends the check with a protocol error.

## Gateway

- A server request reusing a pending `tools/list` id no longer consumes it.
- Windows only: a non-string `method` or tool name, a non-object `params`, or a
  repeated key no longer throws out of the relay. Messages are read last-wins,
  as the client and server read them.
- A tool result with `isError: true` is logged as a failure.

## Write pipeline (§6)

- An edit to a server switched off in a presence-only client updates the held
  copy, by splicing, and the server stays off. A definition back in the file
  outranks a stale held copy; switching on never overwrites one.
- Edits splice only command, args, url, transport and env (key by key) into the
  existing definition. `headers`, `cwd`, `envFile`, Codex's
  `startup_timeout_sec`, `enabled_tools`, `http_headers`,
  `bearer_token_env_var` and `enabled = false` survive, a Save with no changes
  writes nothing, and a rename rewrites only the key or the TOML headers. Dotted
  `env.KEY` in Codex is refused.
- Codex tables that are not adjacent are replaced and removed run by run.
- Every write looks a server up by identity and uses the file's own spelling; a
  key written twice, or two keys with one identity, is refused.
- Rotating a secret updates held copies and refuses to create a missing key.
- A restore clears only the held copies of servers the backup defines, read from
  the backup itself.
- A config that is a symbolic link is written through to its target; rolling
  back a file that did not exist removes the created target, not the link.
  Kytto's own storage never follows a link.
- The config watcher hands a pending change to the watcher that replaces it and
  watches a missing or recreated directory from its nearest existing ancestor.
- "Restrict permissions" fails when there is no file or the file is still
  readable by others.

## Shell and web UI

- The tray falls back to the automatic client when the chosen one is
  uninstalled or read-only; `library.scan` runs off the UI thread.
- Busy sheets ignore Esc and the backdrop, failures land on the sheet that
  started the request, and double submits are gated. Panels restore their scroll
  position by key. Contract Guard alerts raised by a check produce a notice.
- Client names instead of ids, "% of 200k" read from the reported window, tool
  mask counts against the tools on offer, URL redaction in the diagnostic
  report, a matrix that keeps two and a half rows at the minimum window, and
  `dev.html` fixtures for every command the page sends.

## Compatibility

No IPC command was added. `contract.acknowledge`, `health.check` and
`secrets.restrictPermissions` behave as described in [`../ipc.md`](../ipc.md).
`metadata.json` gains `lastPassingTools`; records written by 1.0.7 stay
readable, and their `contractTools` serve as the last passing tools until the
next passing check.
